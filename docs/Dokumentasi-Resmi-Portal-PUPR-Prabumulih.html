1. Ringkasan Eksekutif

Conweb.id telah mengembangkan Portal Digital Dinas PUPR Kota Prabumulih sebagai pusat informasi publik dan sistem pengelolaan konten terpadu yang responsif, aman, mudah dikelola, dan dapat dikembangkan.

Portal menggabungkan website publik, CMS administratif, publikasi berita, layanan publik, proyek infrastruktur, transparansi dokumen, agenda, galeri media, pengaduan masyarakat, pencarian konten, serta asisten informasi berbasis basis pengetahuan resmi.

Laravel 12Fondasi aplikasi

Status implementasi: portal telah dipasang pada lingkungan production dan dapat diakses melalui domain resmi puprprabumulih.id.

2. Tujuan dan Ruang Lingkup

2.1 Tujuan

  • Menyediakan kanal informasi resmi Dinas PUPR yang cepat, terstruktur, dan mudah diakses masyarakat.
  • Memudahkan petugas mengelola konten tanpa perlu mengubah kode program.
  • Meningkatkan transparansi program, proyek, dan dokumen publik.
  • Menyediakan pencatatan pengaduan masyarakat secara tertib melalui nomor tiket.
  • Menyediakan fondasi digital yang dapat diintegrasikan dengan layanan pemerintah lainnya.

2.2 Ruang Lingkup Pekerjaan

  • Analisis kebutuhan dan struktur informasi.
  • Perancangan tampilan website publik dan dashboard CMS.
  • Pengembangan backend, database, autentikasi, otorisasi, dan audit aktivitas.
  • Migrasi serta penataan konten dan media dari sumber website sebelumnya.
  • Deployment ke hosting, konfigurasi HTTPS, database, storage, dan optimasi production.
  • Pengujian fungsional dan penyusunan dokumentasi resmi.

2.3 Batasan

Integrasi eksternal seperti SSO pemerintah, WhatsApp API, GIS interaktif, tanda tangan elektronik, object storage, dan AI generatif eksternal tidak termasuk kecuali disepakati melalui pekerjaan lanjutan.

5.2 Persyaratan Pengelola

  • Perangkat dengan browser modern dan koneksi internet stabil.
  • Akun CMS individual; akun tidak boleh digunakan bersama.

  • Dokumen publik harus dipastikan bebas data pribadi/rahasia sebelum diterbitkan.

8. SOP Operasional CMS

8.1 Membuat Konten

  1. Masuk melalui halaman /admin.
  2. Pilih modul dan klik Tambah data.
  3. Lengkapi judul, ringkasan, isi, media, status, dan metadata SEO.
  4. Gunakan status DRAFT selama penyusunan.
  5. Lakukan preview dan verifikasi isi, tautan, tanggal, serta gambar.
  6. Ubah status menjadi PUBLISHED setelah memperoleh persetujuan.

8.2 Standar Editorial

  • Gunakan Bahasa Indonesia yang jelas dan sesuai kaidah.
  • Judul harus ringkas, faktual, dan tidak menyesatkan.
  • Setiap gambar wajib memiliki alt text yang menjelaskan isi gambar.
  • Hindari menyalin format dari aplikasi lain secara berlebihan.
  • Jangan menerbitkan NIK, nomor pribadi, dokumen internal, atau data sensitif.
  • Pastikan sumber, tanggal, lokasi, dan penanggung jawab informasi benar.

8.3 Pengaduan

  1. Periksa laporan baru dan validasi kelengkapan lokasi/kontak.
  2. Ubah status menjadi VERIFIED atau REJECTED sesuai hasil verifikasi.
  3. Tetapkan proses tindak lanjut dan catat progres pada catatan internal.
  4. Isi respons publik secara sopan, jelas, dan tidak membuka data internal.
  5. Ubah menjadi RESOLVED setelah penanganan selesai.

9.2 Prosedur Pembaruan

  1. Buat backup database dan media.
  2. Aktifkan maintenance mode bila perubahan berisiko.
  3. Tarik source versi yang telah diuji.
  4. Jalankan Composer menggunakan mode production.
  5. Jalankan migration dengan opsi force.
  6. Pasang bundle frontend hasil build.
  7. Bersihkan dan buat ulang cache konfigurasi, route, dan view.
  8. Lakukan smoke test halaman publik, login, CRUD, media, dan health endpoint.
Catatan: perubahan production hanya dilakukan oleh petugas teknis yang ditunjuk. Jangan mengedit file vendor atau source langsung dari File Manager.

10. Keamanan Sistem

  • HTTPS untuk seluruh trafik.
  • Session authentication dan regenerasi session saat login.
  • CSRF protection pada form dan request perubahan data.
  • Rate limiting pada login, pengaduan, dan asisten.
  • Validasi tipe serta ukuran upload.
  • Role-based access control untuk setiap modul.
  • Sanitasi konten rich text terhadap script dan event berbahaya.
  • Audit log untuk aktivitas administratif.
  • Source dan konfigurasi rahasia berada di luar document root.
  • Production debug dinonaktifkan.

10.1 Kewajiban Keamanan Pengelola

  • Mengganti password awal dan menyimpan kredensial pada password manager.
  • Tidak mengirim password melalui grup chat atau dokumen umum.
  • Melakukan review pengguna minimal setiap tiga bulan.
  • Memasang pembaruan keamanan setelah pengujian.
  • Melaporkan dugaan kebocoran atau perubahan tidak sah kepada penanggung jawab.

12.1 Dukungan dan Perubahan

Perbaikan bug, pemeliharaan, penambahan fitur, perubahan desain, atau integrasi baru dilaksanakan sesuai ruang lingkup dukungan/kontrak yang disepakati antara Dinas PUPR Kota Prabumulih dan Conweb.id.

13. Pengujian dan Kriteria Penerimaan

13.1 Pengujian yang Dilakukan

  • Automated test aplikasi dan assertion fitur utama.
  • Build frontend production.
  • Migration dan seeding database production.
  • Smoke test seluruh halaman utama.
  • Pengujian login serta akses halaman Create CMS.
  • Pengujian file CSS, JavaScript, gambar, storage, dan health endpoint.
  • Pengujian kontrol akses role.

13.2 Checklist UAT

  • Identitas, logo, alamat, dan kontak instansi telah diverifikasi.
  • Menu serta struktur informasi telah disetujui.
  • Admin dapat login dan mengganti password.
  • Admin dapat membuat, mengubah, preview, menerbitkan, dan menghapus konten.
  • Gambar dan dokumen dapat diunggah serta diakses.
  • Form pengaduan menghasilkan nomor tiket.
  • Role pengguna sesuai kewenangan.
  • Website responsif pada desktop dan perangkat mobile.
  • Backup awal telah tersedia.
  • Dokumentasi dan akses telah diterima pihak Dinas.

Checklist di atas diisi pada saat User Acceptance Test bersama perwakilan instansi.
